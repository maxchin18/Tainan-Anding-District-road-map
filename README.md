# 臺南市安定區公眾通行道路圖資系統

🔗 **線上版**：https://maxchin18.github.io/Tainan-Anding-District-road-map/

查詢安定區 13 里的農路、產業道路、區道，讓民眾回報路面問題，並公開施工／維修案件。
純靜態網站（GitHub Pages），手機、電腦都能用，也可「加入主畫面」當 App 使用。

| 頁面 | 對象 | 說明 |
|---|---|---|
| `index.html` | 民眾 | **雙模式入口**：快速通報（輕量版 `?mode=lite`）／完整查詢版（道路圖資、施工公開、工具、公告） |
| `index.html#case=案號` | 全民 | 案件頁：進度時間軸、施工前中後照片、民眾評分、案件留言板 |
| `vendor.html` | 廠商 | 廠商回報中心：專屬密碼、派工清單、精準導航、上傳履約證明、一鍵產製施工照片（含 QR） |
| `admin.html` | 公所 | 管理後台：審核派工、三道防弊檢核、驗收／退回、代為登錄、契約預算、帳號、數位軌跡 |
| `verify.html?c=驗收碼` | 全民 | QR-Code 驗收文件驗證：比對資料庫原始照片與數位指紋 |

## 系統介紹文件對照

依山上區公所「公眾通行道路圖資系統」介紹的架構與功能逐項實作：

### 技術架構（零預算）

| 項目 | 本系統 |
|---|---|
| 後端資料庫與邏輯 | Google Sheets ＋ Apps Script（`gas/Code.gs`） |
| 前端 GIS 地圖引擎 | Leaflet.js 1.9.4（國土測繪中心底圖、地籍圖） |
| 推播通知 | LINE Messaging API ＋ Email（MailApp） |
| 靜態前端托管 | GitHub Pages |

### 六階段數位閉環

| 階段 | 功能 | 實作位置 |
|---|---|---|
| 一、民眾線上通報 | 雙模式入口分流 | 首頁「快速通報／完整查詢」，輕量版只保留通報流程、大按鈕 |
| | AI 端點隱私運算去識別化 | `js/deid.js`：MediaPipe 在**民眾裝置上**偵測人臉、人物、車輛，自動馬賽克人臉與車牌區域，可手動塗抹補強；只上傳處理後影像（同時移除 EXIF） |
| | 語音／鍵盤雙軌輸入 | 說明欄 🎤（瀏覽器語音辨識，zh-TW） |
| | 防機器人驗證碼 | 後端產生的筆畫數字圖（非文字節點）、一次性、10 分鐘有效；另有隱藏陷阱欄位 |
| | 時間及空間雙重演算法警示 | 選定位置後即比對 3 年內、方圓 50 公尺內的通報與歷史維修，提醒可到原案留言 |
| | Email／LINE 雙軌進度通知 | 填 Email 即收信；成功頁「LINE 接收進度」一鍵綁定 |
| 二、系統自動立案 | 自動給號、地圖點位、雙軌通知民眾、通知本所多組信箱 | 鎖定下產生唯一案號（`AD1151008-001`）並寫入雜湊鏈；通知信箱可設多組 |
| 三、後台審核派工 | 地籍圖交叉比對 | 後台一鍵套疊地籍圖；計算距最近公眾通行道路距離；未勾選確認則後端拒絕派工 |
| | 時空警示＋會勘簽核 | 3 年內 50 公尺內有案件時，須填簽奉核可文號，後端強制檢核 |
| | 預算控管，超額派工自動阻斷 | 派工金額超過契約剩餘額度即跳出警示並清除輸入；後端再次阻斷 |
| | 排程派工、雙軌通知 | 排程施工日期顯示於案件頁；派工即通知民眾 |
| 四、廠商施工驗收 | 精準導航、專屬密碼、無紙化上傳 | `vendor.html`；廠商只看得到自己的派工；更換廠商即停用帳號，舊登入立即失效 |
| | 上傳即通知民眾並公開 | 完工回報後 Email／LINE 通知，施工前後照片公開於案件頁 |
| | 一鍵產製施工前中後照片 | A4 列印版（可存 PDF），每張照片印有數位指紋 |
| | QR-Code 數位防偽驗收鏈 | 回報當下產生唯一驗收碼與照片組雜湊；掃碼到 `verify.html` 重新計算 SHA-256 比對；退回即作廢 |
| 五、民眾回饋 | 星級評分、案件留言板、雙向溝通 | 憑查詢碼評分；留言需驗證碼，留言即通知本所；公所回覆通知民眾；後台可隱藏不當留言；後台顯示平均評分 |
| 六、資料開放 | 去識別化 CSV | 案件編號、通報／派工／完工／驗收日期、TWD97／WGS84 雙座標、搶修類型、施工廠商、決標金額、評分 |

### 五道廉能防弊機制

| # | 機制 | 實作 |
|---|---|---|
| 01 | AI 端點隱私運算去識別化 | 原始照片從未離開裝置，伺服器只收到去識別化影像 |
| 02 | 時間及空間雙重演算法警示重複派工 | 前端（民眾通報）與後台（派工）兩道獨立比對；後台未填會勘簽核文號不得派工 |
| 03 | QR-Code 數位防偽驗收鏈 | 驗收碼綁定照片 SHA-256；任何照片替換都會指紋不符 |
| 04 | 地籍圖比對防私路公修 | 派工前必須套疊地籍圖確認，後端強制 |
| 05 | 預算控管，超額派工自動阻斷 | 前端阻斷輸入＋後端拒絕 |

此外所有關鍵事件寫入 **SHA-256 雜湊鏈「數位軌跡」**，管理者可一鍵驗證；直接竄改試算表任何一列都會被驗出（斷鏈位置）。

### 照顧數位弱勢（SDG 10.3）

- 承辦人可「代為登錄」電話、里幹事協助、臨櫃或巡查發現的案件，一樣自動立案與通知。
- 24 小時線上通報；輕量版大字大按鈕；緊急狀況提示撥打 1999。

### 已知限制

- **車牌偵測**：沒有可在瀏覽器執行的開源車牌模型，系統以「偵測車輛 → 遮蔽車頭／車尾下半部」處理，並要求民眾目視確認、手動補強。
- **LINE**：需公所申請 LINE 官方帳號並完成後台設定；Apps Script 無法驗證 LINE 簽章，以查詢碼防止冒綁。
- **不可竄改**：試算表本身仍可被有權限者編輯，系統提供的是「竄改可被驗出」的雜湊鏈，並非區塊鏈。
- **語音輸入**：依瀏覽器支援（Chrome、Edge、Android、iOS Safari 新版）；不支援時自動隱藏按鈕。

## 參考網站分析與改進

參考對象：[臺南市山上區公眾通行道路圖資](https://smalldeer22-cpu.github.io/Tainana-Shanshang-District-farm-road-map/)

### 優點（保留）

- 依角色分流（民眾通報／公開查詢／廠商回報／巡查）
- 維修案件依年度分層公開，有里別統計，透明度高
- 座標工具支援 TWD97，貼近公所實務（登革熱半徑查詢、案件定位）
- 通報流程有照片與 GPS
- PWA，可加入手機主畫面

### 缺點與本系統的改進

| 參考網站的問題 | 安定區版的做法 |
|---|---|
| 單一 480 KB HTML，樣式大量 `!important`，難維護 | 拆成 `index.html`／`css`／`js`／`data`，設定集中在 `js/config.js` |
| 後端金鑰 `appKey` 寫在前端、密碼放在網址參數 | 前端不放任何密鑰；密碼以 POST 傳送，後端加鹽雜湊驗證、簽章權杖、錯誤鎖定、角色權限（見 `gas/`） |
| 公開清單含民眾描述，個資界線不清 | 公開看板只顯示類別／位置／狀態；說明、照片、聯絡方式僅後台登入者可見，檢視者另遮罩聯絡方式 |
| 每次開啟都載入 TensorFlow（約 1 MB 以上），手機很慢 | 只載入 Leaflet、proj4、exifr-lite，首頁輕量 |
| CDN 未鎖版本（`unpkg.com/leaflet`），哪天更新就可能壞掉 | 所有套件鎖定版本 |
| 道路選單是 100 多項的下拉清單，難找 | 即時搜尋＋關鍵字高亮、依等級晶片與里別篩選、依長度／名稱排序 |
| 所有道路同一個藍色，沒有圖例 | 五級道路分色＋白色描邊（插畫風）、常駐圖例、粗細隨縮放調整 |
| 開啟時有遮擋地圖的選單 | 首次導覽可關閉、可「不再顯示」；之後直接進入地圖 |
| `user-scalable=no` 禁止縮放，不利長者與視障 | 允許縮放、鍵盤可操作、ARIA 標記 |
| 登革熱分頁與座標工具功能重複 | 合併為「座標定位／半徑查詢」 |
| 選取道路後無法分享 | 每條道路有固定網址（`#road=AD07-001`），可直接傳 LINE |
| 手機上側欄佔滿畫面 | 底部抽屜（三段：收合／半開／全開），拖曳地圖時自動收合 |

### 視覺風格

以扁平插畫資訊圖表為參考：米白紙底、粗墨色描邊與實心陰影、品牌藍標題、紅色重點、
橘色蜿蜒道路、藍色河流與綠色田野（頁首插畫即安定區曾文溪畔的意象）。

## 維護

```
index.html            頁面

data/villages.geojson 里界＋各里道路統計
data/boundary.geojson 區界
data/cases/           施工／維修案件（格式見該資料夾 README）
data/news.json        公告
data/raw/             OSM 原始資料
admin.html            管理後台（js/admin.js）
vendor.html           廠商回報中心（js/vendor.js）
verify.html           QR-Code 驗收文件驗證（js/verify.js）
js/common.js          共用工具（API、驗證碼、開放資料、施工照片文件產製）
js/deid.js            AI 端點去識別化

gas/                  後端（Google Apps Script）＋部署說明
scripts/              資料處理腳本、本機測試伺服器 dev_server.js
```

### 更新道路圖資

```bash
# 1. 重新下載 OSM 原始資料（Overpass API）
curl -o data/raw/roads_osm.json --data-urlencode "data@scripts/q_roads.txt" https://overpass-api.de/api/interpreter
curl -o data/raw/vil_osm.json  --data-urlencode "data@scripts/q_vil.txt"  https://overpass-api.de/api/interpreter
# 2. 重新產生 GeoJSON
python scripts/build_data.py
```

### 新增施工案件

```bash
python scripts/cases_csv_to_geojson.py 115養護.csv --year 115 --label "115年道路及公共設施養護維修"
```

### 新增公告

編輯 `data/news.json`，加一筆 `{ "date": "2026-10-08", "title": "…", "body": "…" }`。

### 啟用民眾通報與管理後台

依 [`gas/README.md`](gas/README.md) 部署 Apps Script、建立帳號，把網址填入 `js/config.js` 的 `reportEndpoint`。
未設定時，通報會暫存在使用者手機並產生可列印的通報單，後台無法登入。

本機可用模擬後端測試完整流程：`node scripts/dev_server.js`（直接執行 `gas/Code.gs`，說明見 gas/README.md）。

### 本機預覽

```bash
python -m http.server 8765
```

> 更新 css／js 後，請把 `index.html`、`admin.html` 中的 `?v=…` 版本號改掉，避免使用者瀏覽器讀到舊檔。
