# 後端部署（Google Apps Script）

網站本身是純靜態（GitHub Pages），通報、派工、驗收、留言等功能需要一個後端。用公所的 Google 帳號即可**零預算**架設，資料只存在公所自己的 Google 試算表與雲端硬碟。

## 一、部署後端

1. 建立一份 Google 試算表，命名如「安定區公眾通行道路案件」。
2. 試算表選單 **擴充功能 → Apps Script**，把 `Code.gs` 內容整份貼上、儲存。
3. 在 `addAccount()` 填入第一個管理者帳號與密碼（至少 10 碼），選此函式按 **執行**並授權。
   **執行完立刻把密碼改回空白再儲存。**
4. 右上 **部署 → 新增部署作業**，類型選「網頁應用程式」：執行身分 **我**、誰可以存取 **所有人**。
5. 複製「網頁應用程式網址」（`https://script.google.com/macros/s/…/exec`），填入 `js/config.js` 的 `reportEndpoint`，推上 GitHub。

> 之後修改 `Code.gs`：「部署 → 管理部署作業 → 編輯 → 版本選『新版本』」，網址不變。

系統會自動建立四張工作表：**案件**、**開口契約**、**留言**、**數位軌跡**（欄位以名稱對應，可調整欄序；系統升級新增欄位時會自動補上）。

## 二、登入後台完成設定

以管理者登入 `admin.html`：

1. **開口契約**：建立年度開口契約（契約名稱、廠商、年度、限額）。派工時會自動加總，超額即阻斷。
2. **帳號**：建立承辦人、檢視者與**廠商帳號**（廠商帳號需填廠商名稱，須與契約上的廠商名稱一致）。
3. **設定**：填入本所通知信箱（可多組）。

| 角色 | 可以做的事 |
|---|---|
| 廠商 | 只能登入 `vendor.html`；只看得到自己契約的派工；上傳施工前／中／後照片與履約文件 |
| 檢視者 | 看案件、地圖、照片；聯絡方式與 Email **遮罩** |
| 承辦人 | ＋ 派工、驗收、退回、代為登錄、回覆留言、隱藏留言 |
| 管理者 | ＋ 開口契約、帳號、設定、匯出、數位軌跡驗證 |

**更換廠商時**：在「帳號」停用舊廠商帳號或重設密碼；任何帳號變更都會讓該帳號既有的登入立即失效。

## 三、LINE 推播（選用）

1. 在 LINE Developers 建立 Messaging API 頻道（公所官方帳號）。
2. 後台「設定」貼上 **Channel Access Token**（只寫入、不顯示）。
3. LINE 頻道的 **Webhook URL** 設為後端網址（同 `reportEndpoint`），並開啟 Use webhook。
4. `js/config.js` 填入 `lineOaId`（如 `@123abcde`）。

民眾通報成功後按「LINE 接收進度」，會自動帶入「追蹤 案號 查詢碼」訊息；送出後即綁定，之後派工、完工、驗收、公所回覆都會推播。沒有查詢碼無法綁定他人案件。

> Apps Script 無法讀取 HTTP 標頭，因此無法驗證 LINE 簽章；以「查詢碼」作為綁定憑證來防止冒綁。

## 四、六階段數位閉環對應

| 階段 | 後端機制 |
|---|---|
| 一、民眾線上通報 | `report`：防機器人驗證碼（筆畫繪製、一次性、10 分鐘有效）、座標範圍與類別白名單、流量上限；照片已在民眾裝置完成 AI 去識別化 |
| 二、系統自動立案 | 鎖定下給號 `AD+民國年月日-流水號`；寫入雜湊鏈；Email／LINE 通知民眾；通知本所多組信箱 |
| 三、後台審核派工 | `adminDispatch` 三道防線：未確認地籍 → 拒絕；3 年內 50 公尺內有案件且無簽核文號 → 拒絕；超過契約限額 → 拒絕 |
| 四、廠商施工驗收 | `vendorUpload`：只能回報自己的案件；計算每張照片 SHA-256 與照片組雜湊；產生唯一驗收碼（QR-Code）；退回時舊驗收碼作廢 |
| 五、民眾回饋 | `rate`（須查詢碼）、`comment`（須驗證碼）；有留言即通知本所；公所回覆通知民眾 |
| 六、資料開放 | `list` 只輸出去識別化欄位：案號、日期、雙座標、類型、廠商、金額、狀態、評分 |

## 五、安全設計

| 項目 | 做法 |
|---|---|
| 密碼 | 加鹽、雜湊 2000 次後存在「指令碼屬性」，試算表與程式碼中都沒有明文 |
| 登入權杖 | HMAC-SHA256 簽章，8 小時到期；存在 sessionStorage，關閉分頁即登出 |
| 暴力破解 | 同一帳號連錯 5 次鎖 15 分鐘；全站 15 分鐘內錯 50 次暫停所有登入 |
| 權限 | 每個請求都在後端重新驗證角色；廠商與公所人員的 API 完全分開 |
| 個資 | 公開 API 不輸出說明、聯絡方式、Email、民眾照片；檢視者另遮罩 |
| 檔案 | 只能讀取該案件本身登記的檔案，無法藉此讀取雲端硬碟其他檔案 |
| 數位軌跡 | 每個事件（立案、派工、回報、退回、驗收、評分、留言、登入、帳號與契約變更）寫入 SHA-256 雜湊鏈，鏈頭另存於指令碼屬性；直接修改試算表會在驗證時斷鏈 |
| 試算表 | 所有文字強制以文字寫入，防公式注入，也避免電話開頭 0 遺失 |

## 六、本機測試

不用部署也能測試全部流程。`scripts/dev_server.js` 會**直接執行這份 `Code.gs`**，以記憶體模擬試算表、雲端硬碟、Email 與 LINE：

```bash
node scripts/dev_server.js
```

開 http://localhost:8766 。測試帳號 `demo-admin`／`demo-handler`／`demo-viewer`／`demo-vendor`，密碼 `local-test-only`（只在本機模擬伺服器有效，與正式後端無關）。寄出的信可在 http://localhost:8766/__mail 查看。
